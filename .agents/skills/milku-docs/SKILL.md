# Milku 文档

<!-- SPDX-License-Identifier: LicenseRef-Milku-Commercial-1.0 -->

- 用户文档放在仓库 `docs/`；历史架构留在 Git 历史和归档中，不混入当前已实现能力。
- 正文使用中文，保留必要的指令助记符、信号名和代码标识。
- 页面左上角只放小写 `milku`。标题直接写主题，标题下不放英文翻译、装饰性副标题、宣传语或重复解释。
- 白底黑字、细线框。用字号和字重表示层级与强调；表格列出可比较的信息。不用渐变、阴影、图标、彩色卡片或大面积装饰。
- 提高可视化程度：结构关系用框图，执行过程用流程图，寄存器／编码用位域图，访存用地址与字节示意图。图与表互补，避免整份文档只有文字表格，也不为凑图添加装饰图片。
- 技术示意图优先使用可编辑 SVG，黑白线框、清楚的箭头和足够大的中文标签；标明位宽、方向或必要的例值。图中例子要与指令语义一致，不能把简化流程画成精确周期。HTML 和 PDF 使用同源图形。
- 优先写事实、参数、行为与限制，删掉寒暄、引言套话、重复总结和不帮助查阅的说明。准确性所需的注释不能省略。
- 文档不设空白封面。首屏直接呈现有效内容。需要分页时使用 A4；表头可重复，表格行不跨页，避免孤立标题、裁切、溢出和过小文字。
- 有版式要求时保留可编辑 HTML，PDF 从同一 HTML 导出。HTML 不依赖外部字体、脚本或在线样式。参考 `docs/lavaneko.html` 的现有样式，避免复制多个易漂移的模板。
- 技术内容以当前源码和可核验的上游规范为依据；记录基线提交与源码定位。区分实际实现、架构规定和未来计划，不把后续型号指令或拟议扩展写成现有能力。
- 指令集文档至少覆盖寄存器、数据宽度、寻址、助记符与操作、条件码、特权、异常、编码和源码入口。用分组表格压缩内容，不能为了简短遗漏整个指令族。
- 修改文档后核对助记符覆盖、源码位置和链接。导出 PDF 后检查页数、提取文字并逐页查看渲染结果；生成过程和临时图片不进入交付目录。

当前工程同时保留 R32 v1 标量兼容入口（20 条指令）和 R32 SIMD v1 并行入口（增加 LANEID、COREID、TASKID，共 23 条）。并行入口默认为 4 核心 × 16 lane，支持启动掩码与统一分支，每 lane 使用 DSP 乘法和迭代除法；不支持分歧恢复、浮点、图形流水线或 DDR/PCIe 集成。Vivado 验证范围和实际结果见 docs/gpu-validation.md。
